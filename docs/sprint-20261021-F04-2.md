### EVD-1 — the empty case is not asserted as a contract

What is not held: that each checker, given nothing to work with, exits 0 with its defined shape rather than
raising. Held for the handful whose tests construct the case.

- **E1-a.** Every job the registry plans in `live` mode, run as the runner runs it (its own process,
  `run_script`), against a site that refuses every connection (a closed port on this machine), with every
  operator input supplied as an empty file: none comes back `crash`, `bad_output` or `signal`. Expected: **most
  green; any red is a defect repaired here with the test red first.** I cannot say which; the port census of
  0.173.0 found three `crash`es under a refusal, all repaired, and an empty artifact is a shape no test has
  handed most of them.
- **E1-b.** The same jobs against a site that answers 200 with an empty body (nothing to parse): the same
  requirement. Expected as E1-a.
- Third scenario (output that is not one JSON document → `bad_output`): expected **already held** by the
  runner's `run_script` tests; confirmed by mutation, not assumed.
- If both hold → `enforced`. No verdict moves unless a checker is repaired, and a repaired one moves from
  `NO_DATA` (crash) to `NO_DATA` (its own reason) — a label, not a status.

### EVD-2 — uniqueness of the translation is unread; a fifth word passes through

- **E2-a.** Four call sites in `checklist_runner.py` each spell `SEVERITY_ALIAS.get(x.lower(), x.lower())`.
  That is one table and four translations. Repaired as one function; a test reads the source and refuses
  any other reference to the table, and any other mapping of an alias word onto the four anywhere in the
  shipped scripts. Expected **red on the source as it stands** (four sites).
- **E2-b.** A fifth word on the checker side: a `none_severity` rule over an issue whose severity normalises to

  at all. No checker emits such a word today (every literal severity in `scripts/` lowercases to one of
  `critical high medium low error warning warn info notice`, measured before writing this line), so **no live
  verdict is expected to move**; a test holds the static census so a new literal outside the set reddens.
- **E2-c.** The rule side: `audit_assertions.py` already refuses a rule asking for a severity its script cannot
  emit; a registry rule naming a word outside the four and the aliases is expected **refused already**,
  confirmed by mutation.
- If all hold → `enforced`.

### VRD-2 and VRD-3 — the sourceless gap

What is not held: an item answered by a person or a model (72 items, `source: llm | manual | gsc` with no
rule) cannot carry `applies_when`, which lives inside a rule.

- That gap is a schema gap and **not a verdict bug**: a registry declaration over an item with no script output
  would have nothing to evaluate. For those items the answer is where applicability is decided — both merges
  accept `N/A` — and the requirement's substance is that an `N/A` names what was sought.
- **V3-a.** `merge_manual_answers` refuses an answer with no evidence (held already). `merge_llm_answers` takes an
  `N/A` with no rationale and records "no rationale given": an `N/A` that names nothing. Expected **red**;
  repaired by refusing an `N/A` without evidence from the model, as from a person. The item stays
  `LLM_PENDING` (unscored either way, but counted as unanswered): a CHANGELOG line.
- **Narrowing**, both requirements: the applicability declaration is the rule-carrying item's; for an
  answer-carried item it is the answer's `N/A` with its evidence. What is narrowed away and filed: whether a
  model or a person answered `PASS` over a subject the site does not have is that answerer's judgement, which
  no reader here can check (it is `operator-protocol`'s, the queue's instruction to answer `N/A`).
- VRD-2's other half (most items declare nothing) was closed by REG-9 at 0.96.0; its Reader line still says
  otherwise. Expected after the narrowing: both `enforced`, the reader of the rule half being REG-9's sweep
  and `tests/test_runner.py`'s `applies_when` tests, confirmed by mutation.

### REG-1 — the version is held by the generator, not by a reader of this requirement

- → `enforced`. No verdict moves.
