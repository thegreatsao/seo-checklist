### The crawl caps (owner's ruling, 20 October)

F02 criterion 3 failed through `--sample`: with a crawl inventory, `discover_urls` draws the sample from the pages
the crawl read, so the cap decided the pool, and `aggregate_pages` graded the worst sampled page without knowing
the crawl was cut. A sampled PASS could exist only because the cap left out the failing page.

**Fix, if small and safe**: the runner passes the crawl's truncation into `aggregate_pages`; a sampled PASS drawn
from a truncated crawl becomes NO_DATA with the reason; a FAIL or WARN found stands. Then the two basis lines lose
the `--sample` exception (the warn-band floor, which VRD-14 accepts, stays named). "Small and safe" means: only the
sampled aggregation and the line that calls it change, and no verdict moves except that PASS. If it is not, both
constants go back to `inherited` (64 / 66, 161 counted) with the five ledgers.

## Outcome: the crawl caps go back to `inherited`

The aggregation fix was built first and was small: `aggregate_pages` took the crawl's truncation and turned a
sampled PASS into NO_DATA (red first: MS-020 `PASS` 3/3 pages over a three-page crawl of a served site whose
fourth page fails; `FAIL` uncapped). The `gpt-6.1-sol` review then reproduced three more ways the cap decides a
sampled verdict, each run on the code with the fix in:

- **N/A**: CI-016 `N/A` on the two pages a two-page crawl read, `FAIL` with the third (an image with alt
  "image"). Withholding it moves N/A, a verdict beyond the withheld PASS.
- **A pool the cap shrank to one page**: `--crawl-max-pages 1` (or the entry, 99 404s, then the bad page at the
  default 100) leaves fewer than two candidates, the run audits the entry alone, and its PASS stands.
- **A sample the crawl did not supply**: a crawl that read no eligible page falls back to the sitemap, and the
  fix withheld a PASS the cap had not decided, with a reason that named the crawl.

Closing all of them touches `discover_urls` and the single-page branch and moves N/A, which is the ruling's
"not small and safe". So the aggregation change was reverted and both constants are `inherited` again, with
the basis lines naming why. inherited 62 → 64, convention 68 → 66, counted 161, moved together in
`tests/test_inherited_basis.py` (ceiling raised by two on purpose), `tests/known-issues.json`,
`tests/test_registry.py`, `ROADMAP.md`, GOV-2 and EVD-6 (and F11's count). VRD-14 says what is not held under
`--sample`, with both measurements.
