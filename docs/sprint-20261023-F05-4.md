  `safe_browsing.threats`, which the three items read (`len_eq: 0`).

## Scope

- **Each script asks its stand-in only in a loopback-only process, and through the guard.** `SEO_VALIDATOR_STANDIN`
  (in `html_validator.py`) and `SEO_SAFE_BROWSING_STANDIN` (in `domain_safety_check.py`), when set *and*
  `loopback_only()` is true, replace the real endpoint; otherwise they are ignored, so a real audit asks the real
  service exactly as before. The stand-in request goes through `safe_get` / `safe_post`, which under the same switch
  refuse any host but this machine (the real endpoints keep their direct `requests` calls, unchanged). No key is sent
  to a stand-in and none is needed: Safe Browsing's stand-in is asked without one.
- **On a private host the stand-in is asked.** `check`'s private branch keeps naming the host to no outside service,
  and keeps Safe Browsing only when the stand-in plays it (it is this machine). `checklist_runner.STAND_INS` gains
  both scripts, so `private_host_skips` leaves their items to answer; and `has_safe_browsing` is true when the Safe
  Browsing stand-in plays, so `build_plan` does not ask for a key the stand-in does not need.
- **The census serves POST.** `_Quiet` answers a POST from the route table only (reading the body first); any other
  POST is refused as before (501). Rendered-mode validation and Safe Browsing both POST.
- **Two new corpus trees**, `flagged/` and `cleared/`: each answers `/nu/` with a Nu JSON answer and
  `/v4/threatMatches:find` with a Safe Browsing answer — `flagged/` with two markup errors (one `fatal`) and a warning
  and a `SOCIAL_ENGINEERING` match, `cleared/` with no messages and `{}`. `_inputs/<tree>/` holds
  `validator_standin.txt`, `safe_browsing_standin.txt` and a `rendered.json` (TE-181 reads one) under the usual
  placeholder; `corpus_inputs` turns the two `.txt` files into the variables, as it does `pagespeed_standin.txt`.
  New trees, not routes on existing ones, so no answer on an existing tree moves; a twin so each item is seen both
  ways and the census's "never PASS" row stays at 2.
- `tests/census.json` re-recorded; `tests/derived-sets.json` re-recorded for `STAND_INS`; `tests/corpus/README.md`,
  GOV-7, HTTP-3, REG-10, and the README/ROADMAP/KNOWN-ISSUES counts held by `tests/test_prose_counts.py`.
