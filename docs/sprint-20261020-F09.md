Per crawl cap, before its line changes (F02's three conditions):

1. The crawl sets `summary.truncated` when this cap stops the reading.
2. A test drives the cap at its own value, one step past and one step short, and sees `truncated`.
3. Every registry item that reads the crawl either passes by absence and is withheld, reads the entry page only, or
   its verdict is shown not to depend on the unread part.

Found while checking (3), before any edit:

- **The audit does not use these constants.** `checklist_runner.py` passes `--crawl-depth` and `--crawl-max-pages`
  with literal defaults `3` and `100`; `site_crawl.py`'s constants decide only a crawl run by hand. A basis line on a
  number the audit does not read argues nothing. The runner's defaults become the constants.
- **CI-018 was not withheld.** `server_log_audit.py` reads the inventory's `robots_blocked` to find paths crawlers
  requested that robots.txt disallows (`disallowed_paths_crawled`, medium, which CI-018 reads), and never read the
  crawl's `truncated`. A capped crawl discovers fewer refused URLs, so CI-018 could pass clean off the part read.
  Fixed the way the script's other four caveats are: `_incomplete(..., "inventory_truncated", ...)`, so the runner
  withholds the PASS (VRD-14) and a finding made stands.
- **CI-008 and AR-162 could fail on what the cap skipped.** An orphan (`link_profile.py`) is a crawled page no page
  *read* links to. The crawl seeds sitemap URLs at depth 0, so on a capped crawl a page reached from the sitemap is an
  orphan whenever its linker went unread: CI-008 (`high`, `orphan_pages.count eq 0`) failed, and AR-162 (`high`) on
  the same `orphan_pages` issue — and on `low_internal_linking`, an average taken over whichever pages the cap let in.
  Seen FAIL on a served three-page site with a two-page budget. Fixed the LO-198 way: over a truncated crawl the
  script withholds the orphan count (with a reason) and raises neither issue; a dead end, a page read with no
  outbound link, still counts. VRD-14 now names this shape.

**Verdicts move (CI-018 PASS → NO_DATA; CI-008 and AR-162 FAIL → NO_DATA, each only over a truncated crawl), so the
release is minor: 0.170.0.**
