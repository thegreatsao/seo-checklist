### GOV-7 — every gate in the matrix runs offline. Expected: **held, narrowed**, `partial` → `enforced`

The Reader line names three gaps; reading `ci.yml` finds two more. Each is a defect a developer meets (a gate that
fails for npm's outage, or a request nothing reports), so each is held, not narrowed:

- **D7-npx.** The gate step "The specification is a specification" runs `npx -y @fission-ai/openspec@1.12.0`, which
  downloads the package from the npm registry on every CI run (and under the local gate on a machine whose npx cache
  lacks it). Fix: the install step installs the pin; the gate step runs the installed `openspec`. Red first: a test
  that refuses a network fetcher (`npx`, `npm`, `pip`, `curl`/`wget` naming a host that is not this machine, `git`
  `fetch`/`pull`/`clone`/`push`/`ls-remote`) in any `run` line of a step that is not install-only.
- **D7-gates.** Only the `Tests` step carries the tripwire; the other gate steps (smoke runs, the live path, every
  `tools/audit_*` gate) have the guard and nothing under it. Fix: `ci.yml`'s workflow `env` puts `tests/tripwire` on
  `PYTHONPATH` and arms it; an install-only step disarms it (pip reaches PyPI by design); the tripwire's
  `sitecustomize` makes its own directory absolute and first on the child's `PYTHONPATH`, so a child started from
  another directory still loads it, and sets `GIT_ALLOW_PROTOCOL=file` when armed. Red first: a test that every
  non-install `run` step's environment (`ci_local.step_env`) arms it, every install-only step disarms it, and a Python
  started with a gate step's environment from another directory has the tripwire loaded.
- **D7-switch.** The tripwire reads `SEO_LOOPBACK_ONLY`, so a test that clears the guard's switch to exercise its
  public-address policy disarms the tripwire too (the Reader line: "stands both layers down"). Fix: the tripwire has
  its own switch, `SEO_TRIPWIRE`, set by `tests/harness.py` and `ci.yml`. Red first: with `SEO_LOOPBACK_ONLY` cleared,
  a public name lookup in the test process still raises. Expected on the full run: none of the tests that clear
  `SEO_LOOPBACK_ONLY` (`test_safe_http`, `test_crawl_no_answer`, `test_port_refusal_census`, `test_runner`,
  `test_tls_certificate`, `test_url_credentials`) reaches a public host; one that does is a finding, recorded below.
- **D7-binary.** A non-Python binary a Python process starts is unseen. Fix: the tripwire also hooks
  `subprocess.Popen`, `os.system`, `os.posix_spawn` and `os.exec`: a program that is not Python and not named in its
  list, with the reason it is held offline, is refused (raised in the test process, the child ended). Expected list:
  `git` (`GIT_ALLOW_PROTOCOL=file`), `bash` (`ci_local` runs the workflow's lines, read by D7-npx's test), `node`
  (the report's own script over a local file, `test_report`); `whois` is not listed (`domain_safety_check` never starts
  it under the switch) and neither is the `notebooklm` CLI. Python is recognised as `sys.executable`, a `python*`
  name, or a file whose first line names python. A binary the full run starts that is not expected here is a finding.
  Red first: a child starting a binary not on the list is ended.
- **D7-alone.** 20 of 79 test modules do not import `tests/harness.py`, so run alone they have neither switch nor
  tripwire. Fix: each imports it; a test refuses a `tests/test_*.py` that does not. Red first.

**Narrowed, and the Reader line says so:** the setup steps (`actions/checkout`, `actions/setup-python`, install-only
lines) reach the network by design and are not gates; a shell command in a gate step's own lines is read by the word
list above, not watched by the hook; a listed binary is trusted on its reason. None is a verdict.

Mutations, one at a time, each running only its named module: tripwire back on `SEO_LOOPBACK_ONLY`; the workflow's
tripwire `env` removed; an install step left armed; `npx` restored; `bash` removed from the binary list (a test that
starts it goes red); `import harness` removed from one module; the absolute-`PYTHONPATH` rewrite removed.
