**The seam.** Batch 4 noted the scripts call Google through `googleapiclient`, not `safe_http`. All four get their
client from one function, `gsc_checker.build_service`, and use three call chains of it and nothing else:
`searchanalytics().query(siteUrl, body)`, `sitemaps().list(siteUrl)`, `urlInspection().index().inspect(body)`, each
`.execute()`d. `googleapiclient` is an optional extra (`pyproject.toml` `gsc`) and is not installed in CI or here, so
a recorded discovery document cannot be the seam: `build_service` returns, before it checks for the extra or reads
the key file, a small client speaking those three chains over Google's own REST paths to the stand-in. Under the
switch only; otherwise `build_service` is untouched.

Shapes, from Google's reference (developers.google.com/webmaster-tools/v1, read 23 October 2026) and the parsers:
- `searchanalytics.query`: `POST /webmasters/v3/sites/{siteUrl}/searchAnalytics/query`, `siteUrl` URL-encoded;
  answer `{rows: [{keys, clicks, impressions, ctr, position}], responseAggregationType}`, one key per requested
  dimension in request order. The scripts ask `["query", "page"]` (checker, cannibalization) and `["page"]`
  (checker's top pages, reconcile), so the stand-in answers by the request's `dimensions`.
- `sitemaps.list`: `GET /webmasters/v3/sites/{siteUrl}/sitemaps`; answer `{sitemap: [{path, lastSubmitted,
  isPending, isSitemapsIndex, type, lastDownloaded, warnings, errors, contents: [{type, submitted}]}]}`; the longs
  as JSON strings, as Google's discovery APIs send int64 (`detect_issues` reads them through `_as_int`).
- `urlInspection.index.inspect`: `POST /v1/urlInspection/index:inspect`, body `{inspectionUrl, siteUrl,
  languageCode}`; answer `{inspectionResult: {inspectionResultLink, indexStatusResult: {sitemap, referringUrls,
  verdict, coverageState, robotsTxtState, indexingState, lastCrawlTime, pageFetchState, googleCanonical,
  userCanonical, crawledAs}, richResultsResult}}`, enums as the reference lists them.

## Scope

- **`gsc_checker.build_service` returns the stand-in client only in a loopback-only process.**
  `SEO_SEARCH_CONSOLE_STANDIN`, when set *and* `loopback_only()` is true, makes it return the client before anything
  else: the extra is not required and the credentials path is not opened. The client asks through `safe_get` /
  `safe_post`, which under the switch refuse any host but this machine, and sends no key, token or
  `Authorization` header. Otherwise the variable is ignored.
- **The runner passes no credentials when the stand-in plays.** `STAND_INS` gains the four scripts under the one
  variable; `resolve_gsc` returns a fixed marker instead of looking for a key file (so a key on this machine is
  neither found nor passed), only when the mode allows API calls. A private entry still needs `--gsc-property`,
  which is how an operator points a staging copy at a property; the census supplies one.
- **The census serves the paths.** `_Quiet` looks a route up by its decoded path when the raw one is not in the
  table (the property sits in the path URL-encoded), and a table answer may carry `when` (fields the POSTed JSON
  must hold) and `else` (the answer otherwise), which is how one path answers `["page"]` and `["query", "page"]`.
  `corpus_inputs` passes `_inputs/<tree>/gsc_property.txt` as `--gsc-property` and `search_console_standin.txt` as
  the variable; `offline_env` clears the variable.
- **Two new corpus trees**, `unindexed/` and `indexed/`: a homepage that publishes its name (`og:site_name`) and
  declares its canonical, an inner page, a `sitemap.xml` naming both, and `_answers.json` answering the three paths.
  `unindexed/`: inspection says "Crawled - currently not indexed" with Google's canonical the inner page; the
  submitted sitemap carries errors and warnings; four non-brand queries each split across both pages within three
  positions; the brand query lands on the inner page at position 3.4. `indexed/`: "Submitted and indexed", canonicals
  agree, no sitemap errors, each query on one page, the brand on the homepage at 1.0, every page with impressions
  in the sitemap. New trees, so no answer on an existing tree moves.
- `tests/census.json` re-recorded; `tests/derived-sets.json` re-recorded for `STAND_INS`; `tests/corpus/README.md`,
  GOV-7, HTTP-3, REG-10, and the README/ROADMAP/KNOWN-ISSUES counts held by `tests/test_prose_counts.py`.
