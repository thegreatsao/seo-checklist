## Scope

LO-198 (`high`, `local_business_nodes gte 1`) asks whether any crawled page carries LocalBusiness JSON-LD.
`check_local_business_inventory` reads the shared crawl and never looks at `summary.truncated`, so on a crawl the
page or depth cap stopped, "none on the pages read" is reported as a FAIL about the whole site. It is the one
`requires: crawl` item whose failing answer is an absence (the other four read the entry row only).

The runner's truncation rule does not cover it: `passes_by_absence` withholds a clean PASS, and a FAIL stands as a
floor. A runner-wide mirror ("a presence rule that fails on a capped input") would be wrong elsewhere: CI-005,
KW-070 and GO-139 assert `truthy` on values that reading more does not make true. So the fix is the script's, the
way `image_weight_audit.py` already withholds an answer its capped input cannot support:

1. `check_local_business_inventory` carries the crawl's `summary.truncated` out as `truncated`.
2. When it found no node and the crawl was truncated, it does not emit `local_business_nodes`, and says why in
   `truncated_reason`. The runner reads the missing key as NO_DATA. A node found stands: PASS on a capped crawl.
3. The NO_DATA evidence names the reason, not only "`local_business_nodes` missing".

Files: `scripts/local_seo_checker.py`, `scripts/checklist_runner.py` (`_absent` only, for point 3),
`tests/test_evidence_scripts.py`, `resources/references/script-output-shapes.md`, `tools/item-readings.json` if its
reading changes, then the release.
