## Scope

F13 built a sampled-PASS withholding keyed on the crawl's truncation and reverted it: the review reproduced
CI-016 `N/A` over a two-page crawl (`FAIL` over the whole), a pool the cap shrank to the entry alone, and a

enumerating every way the sample pool is built and every status a sampled verdict can take.

### How the pool is built, and what the cap may decide in each case

`discover_urls` takes the entry plus a stride over one source, in this order:

| # | Pool source | When | Can a crawl cap remove a page from it? | Decision |
|---|---|---|---|---|
| P1 | Crawl inventory, complete | the crawl read an eligible page; `summary.truncated` false; the crawl's sitemap set not cut | no | every verdict stands |
| P2 | Crawl inventory, cut | as P1, but `summary.truncated` true **or** the sitemap set the crawl was seeded from is incomplete (byte/URL budget `cut`, files `unvisited`, sitemaps on another host not requested, a sitemap with no HTTP answer) | yes — the page that fails may be one the crawl never read | withhold, by status (below) |
| P3 | P2 collapsed to the entry alone (fewer than two candidates) | e.g. `--crawl-max-pages 1` | yes — the cap is why no other page was sampled | withhold on the entry's page-level rows, by status |
| P3' | P1 collapsed to the entry alone | a complete crawl found one eligible page | no — the site offers one page | stands |
| P4 | Sitemap fallback | the inventory yields no eligible page, or no crawl ran (`page` mode, crawl failed) | not the crawl caps: the fallback does not read the crawl. Its own cut is the first **3** child sitemaps of an index, a bare literal until now | named `SAMPLE_FALLBACK_SITEMAPS` (`convention`); when an index lists more same-host children than it, P2's withholding applies with that reason |
| P5 | Links on the entry page | neither of the above yields a page | no: every anchor is read | stands |
| P6 | None (single page) | nothing yields a page | no | stands |
| — | Operator URLs | the entry is the only URL the operator supplies (`--sample` takes a count, not a list); it is always the first pick | no | as the pool it sits in |

The judgement on P4 after a cut crawl: when a truncated crawl read no eligible page, the cap did decide that the
fallback was used — but the fallback's pool is the sitemap, which no crawl cap shortens. A verdict over it is a
stride sample of the site's own list, the same claim as P1's. That is F13's reviewer finding 3 ("withheld a PASS
the cap had not decided") taken as right.

### What each status does over a cut pool (P2, P3, and P4 cut)

Only page-level items that are sampled (`is_page_level`, not `reads_artifact`) are touched; site-level rows keep
the primary run's verdict, and the crawl readers keep VRD-14's existing handling.

| Status | Over a cut pool | Why |
|---|---|---|
| `FAIL` | stands | a sampled page that fails exists on the site whatever the cap; each page was read whole |
| `WARN` | stands; evidence says it is a floor | VRD-14: a defect found survives and says the measurement is a floor; a page left out could only make it worse |
| `PASS` | `NO_DATA` with the reason | the failing page may be one the cap left out (F13's MS-020 measurement) |
| `N/A` from `applies_when` | `NO_DATA` with the reason | the page the item applies to may be one the cap left out (F13's CI-016 measurement) |
| `N/A` from scope (profile, mode, `--only`) | stands | decided before any page was read; the same on every page |
| `NO_DATA`, `NEEDS_INPUT`, `MANUAL`, `LLM_PENDING` | stand | nothing is claimed |

### CI-018's sitemap side

`server_log_audit.py` counts `sitemap_urls_never_crawled` over the crawl's sitemap set. 0.167.0's walk budgets,
the file cap and the off-host rule can cut that set without setting `summary.truncated`, and the count is then
taken over part of the list while CI-018 passes clean. Fix: a new caveat `sitemap_set_incomplete`, raised by the
same helper the sample pool reads (`site_crawl.sitemap_incomplete`), which marks the answer truncated so the
runner withholds the pass-by-absence; a medium or high finding in the part read stands as a floor.

### Then the caps

Once no sampled verdict is decided by them, `DEFAULT_MAX_PAGES` and `DEFAULT_DEPTH` go to `convention` with the
judgement written: a request and time budget, past which every answer the cap could have decided is withheld or
marked a floor. Callers checked: the runner's `--crawl-max-pages` / `--crawl-depth` defaults read the constants
(since 0.170.0); `site_crawl.py`'s CLI and `crawl()` defaults read them; `anchor_text_audit.py` (25),
`duplicate_content.py`, `link_profile.py`, `internal_links.py` take their own `--max-pages` only when run
standalone, without an inventory — the audit hands them the crawl's.
