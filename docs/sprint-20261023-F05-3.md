## Scope

- **`pagespeed.py` asks a stand-in only in a loopback-only process.** `SEO_PAGESPEED_STANDIN`, when set *and*
  `safe_http.loopback_only()` is true, replaces `PSI_API` as the endpoint; otherwise it is ignored, so a real audit
  asks Google whatever its environment says. The request still goes through `safe_get`, which under the same switch
  refuses any host but this machine: the stand-in can only answer on loopback, and the tripwire stays as it is.
- **A new corpus tree, `slow-field/`, serves the stand-in.** Its `_answers.json` answers
  `/pagespeedonline/v5/runPagespeed` (the path of the real endpoint, any query, so both strategies) with a recorded
  PageSpeed Insights v5 response: `kind`, `id`, `loadingExperience` with CrUX metrics under the API's own names
  (`PSI_METRIC_MAP`'s keys, `percentile` and an upper-case `FAST`/`AVERAGE`/`SLOW` `category`, CLS's percentile
  scaled by 100 as the API reports it), `originLoadingExperience`, `lighthouseResult` (`categories.performance.score`,
  `audits.total-byte-weight.numericValue`, …) and `analysisUTCTimestamp`. The page it reports on is slow for real
  users (LCP, INP, CLS, FCP `SLOW`) and weighs past 1,600 KiB, so each of the seven assertions reaches `fail`.
  `_inputs/slow-field/pagespeed_standin` holds the stand-in's address under the usual placeholder; `corpus_inputs`
  rewrites it to the bound port and hands it to the run as `SEO_PAGESPEED_STANDIN`, as it hands `indexnow_key`.
  A new tree rather than a route on an existing one, so no answer on an existing tree moves.
- `tests/census.json` re-recorded; `tests/corpus/README.md`, GOV-7, REG-10, and the README/ROADMAP/KNOWN-ISSUES counts
  held by `tests/test_prose_counts.py`.
