### ROW_LIMIT: the KW-070/GO-139 defect it waited on

The brand's most-searched query and the page that owns it are picked from the first 5000 rows; a `truthy` rule is
not withheld over `truncated`, so the cap could move KW-070 and GO-139 either way, and an unsearched brand (N/A)
could be one whose rows are past the cap. Fix, kept to the lines that read the row cap: over a truncated read the
script drops `searched`, `ranks_first` and `homepage_ranks_first` from `branded` and writes `branded.reason`,
which the runner already prints with the `NO_DATA` (`_absent`). No other field moves; MS-023 and KW-071 were
already withheld. Small and safe by the starting session's test: only the lines after `find_branded` change, and
the only verdicts that move are KW-070 and GO-139 on a property whose window fills the page.

Expected, declared before running: a full page (brand row + filler to 5000) — KW-070 and GO-139 `PASS` before,
`NO_DATA` after, `branded.reason` naming 5000; the brand row alone — `PASS` both. A full page with no brand row —
`N/A` before, `NO_DATA` after; one generic row — `N/A` both.
