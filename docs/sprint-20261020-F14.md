## Declared before anything was run

Written from HTTP-13 and HTTP-9, before the census probe or any reproduction ran on `1c5b6e5`. The probe's
output fills the census below; it does not decide what is expected.

**O1 — the subject of a script is refused.** When the switch (`SEO_STANDARD_PORTS_ONLY`) refuses the page a
script was asked about (named on another port, or redirecting to one), every item that script feeds is
`NO_DATA` with the row's `error_kind` = `blocked`, and its evidence names the refusal. Not `unread` (that
says the site stopped answering), not `crash` (that says the plugin failed), and never a PASS or FAIL.

**O2 — a secondary request is refused.** When a script reads the subject and the switch refuses a further
URL it needed (a same-host file that redirects to another port, or a URL the page names on one), the item
that URL decides is not decided by the refusal: it is `NO_DATA` with kind `blocked`, or the URL is reported
unchecked (HTTP-9) and the item is decided by what was read. Never a FAIL that reads the refusal as the
site's defect (a key file "not found", a favicon "missing"), never a PASS that counts it as clean.

**O3 — the kind has a sentence.** The runner labels `blocked` in words (today `kind_label("blocked")` is
`unlabelled failure kind 'blocked'`, which is what F13's `tls_certificate.py` fix prints), and
`tools/audit_error_kinds.py` agrees with the vocabulary in both directions.

**O4 — the matrix's cut.** `indexability_matrix.py` reads at most ten sitemap locations. When a sitemap
location past the tenth exists, `in_sitemap` is `null` on every row (not `false`), and the output names the
cut. On exactly ten locations, all read, membership is `true`/`false`. With no sitemap at all (every
location answers 404) membership is `false`, since the site names none and the conventional paths hold
none. Any location the matrix did not read for another reason (no answer, refused, off the host, an index
whose children it does not follow) makes membership `null` with the reason named, for the same reason as the
cut: a URL missing from the files read is not known to be missing.

## Decided while building

- **Only a port refusal excuses a file the page names.** The first fix used the fetch layer's `blocked` for
  the favicon and the stylesheets; that kind also covers a private address, an invalid scheme and a body over
  the limit, and moved a `data:` favicon from FAIL to NO_DATA. Narrowed to `NonStandardPort` there, with a test
  that the `data:` and private-address favicons still fail (DECISIONS.md, 20 October).
- **TECH-002 withholds rather than blames.** A refused stylesheet sets `truncated` with the guard named, as a
  cap does, because fonts can be declared inline; the item is NO_DATA without a kind, inside O2.
- **`canonical_checker --check-targets` unchanged.** By hand only (the registry does not pass the flag); its
  target is a URL the page names, where the same narrowing would apply. Reverted rather than shipped untested.
- **The matrix's cap stays the literal ten** it was (`locations[:10]`, now with `locations[10:]` reported).
  Naming it would add a basis constant and move five ledgers for a number F14 does not change.
- **Probed conventional paths count as locations.** A site declaring eight or more sitemaps pushes the three
  conventional paths past the tenth, and membership is then `null`: strict, and open to the owner's review.
- **HTTP-13 stays `partial`.** Its Reader line had two gaps; F14 closes the `blocked` one. The other, the `www.`
  variant tested for the crawl only, is HTTP-13's, not HTTP-10's, and is out of scope here.
