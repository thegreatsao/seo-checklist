**Found before the contract, by a run (and the reason one item of the plan's group B is not claimed here).** The plan
proposed a tree that answers its entry once and 503 after, so that TE-167's own request would fail where the gate did
not. Served and audited once on a scratch copy of the harness: the run made 13 requests in all, one `GET /`, and TE-167
answered `PASS`. `SEO_HTTP_CACHE` (`safe_http`, "The run-scoped response cache") hands every script the entry answer
the runner's own request got, by design ("every item that reports on a URL now reports on the same bytes"), so
`domain_safety_check.check_uptime` reads the answer the entry gate already judged. `uptime.reachable` is false only on a
5xx or an exception, and the gate stops the run on exactly those (`fails_on: server_error, no_answer`): **TE-167's
assertion cannot report FAIL in a finished audit; only its `entry_answer` does.** That is a finding for the owner (see
Outcome), not a declaration: `CANNOT_FAIL`'s mechanisms are source proofs and none of them is this one.

## Scope

- **The census records which trees the entry gate stopped.** `verdict_census.census()` writes `entry_gated`, the sorted
  labels of the trees whose run reported `entry_reachable: false`. `--check` compares it like every other field, so the
  census job re-derives it on every run. `tests/census.json` is re-recorded with it; no answer in it moves.
- **A FAIL of an `entry_answer` item on a tree the gate did not stop is the assertion's**, because the gate writes
  nothing on such a tree. `observed_failures` claims those, and still refuses the item's FAILs on gated trees, and
  claims none of them from a census that lacks `entry_gated`. Expected claims: CI-001, CI-003 (on `no-location`, whose
  301 entry the gate lets through), CI-015.
- **A tree slow by construction answers a clock item for itself.** `harness.SLOW_BY_CONSTRUCTION` names the served
  trees whose audited page is held back past every `CLOCK_READ` budget by a `delay` in their `_answers.json`
  (`redirect-chain`: 1000 ms against TECH-003's 800). `across_runs` keeps the answer exactly on those trees, so
  `verdict_census.as_held` holds TECH-003's `FAIL` there to the letter and a census in which it moved is out of step.
  `observed_failures` claims a `CLOCK_READ` item's FAIL on those trees only, reading the set from the harness as data
  (as `clock_read` does, and with the same refusal to read a missing name as empty).
- Docstrings (`audit_reachability`'s module and `observed_failures`, `verdict_census.as_held`), REG-10, DEC-12, and the
  README/ROADMAP/KNOWN-ISSUES counts held by `tests/test_prose_counts.py`.
