# Sprint Contract: the specs catch up with 0.167.0–0.169.0 (F10)

**Date:** 2026-10-20
**Feature ID:** F10 (found on 2026-10-20: three releases changed behaviour and no spec moved but a count)
**Estimated sessions:** 1
**Spec requirements touched:** VRD-14, HTTP-1, HTTP-10, HTTP-13 (new), GOV-2; EVD-6's open question (a count only)

## Scope

0.167.0 (`d30ce19`), 0.168.0 (`256b0dd`) and 0.169.0 (`e41295b`) each changed what an audit fetches or answers.
Their spec edits only moved counts, so `openspec/specs/` no longer says what the code does. Each finding below was
checked against the code and its tests before anything is written; one that cannot be confirmed is recorded here as
"not confirmed" and stays out of the specs.

1. **VRD-14 and LO-198 (0.169.0).** `local_seo_checker.py` withholds `local_business_nodes` with `truncated_reason`
   when the crawl was truncated and no node was found, so LO-198 (`gte 1`, a FAIL that is itself an absence) answers
   NO_DATA. VRD-14 says a FAIL on a truncated input survives and does not state this case. Confirmed: the code
   (`check_local_business_inventory`) and `test_lo_198_does_not_fail_a_site_on_the_pages_a_capped_crawl_skipped`.
   VRD-14 gets the case, a scenario, and the test in its Reader line. Which other items share LO-198's shape is
   held by a census test rather than asserted in prose: every non-absence item over a script that can report a cap
   (fourteen), of which three fail on a count of something found — BL-086 and BL-087 count the whole links export,
   which the target cap does not shorten, and LO-198 is the one a cap can fake.
2. **`SEO_STANDARD_PORTS_ONLY` (0.168.0).** `_validated_url` refuses any port but 80 and 443 before resolving, for
   every request, when the switch is set. Confirmed: `lib/safe_http.py` `standard_ports_only`, `NonStandardPort`;
   `test_safe_http.TheWebDeploymentReachesOnlyTheWebPorts` (four tests). No spec names it.
3. **0.167.0.** Confirmed in code and tests:
   - sitemaps on another host are never requested; the crawl and `sitemap_checker` list them in `off_host_sitemaps`
     (`indexability_matrix` skips them without listing them; no item reads that) — `test_sitemap_walk_bounds.OffHostSitemaps`;
   - a walk stops reading new files past `SITEMAP_BYTES_BUDGET` (20 MB), keeps at most `SITEMAP_URLS_BUDGET`
     (50,000) URLs and says what it cut; a gzipped sitemap is decompressed no further than 50 MB
     (`SITEMAP_MAX_UNCOMPRESSED`); `indexability_matrix` got the byte budget in 0.168.0 — `SizeBudget`,
     `test_the_indexability_matrix_stops_reading_sitemaps_past_its_byte_budget`;
   - `tls_certificate.py` connects to `safe_http.validated_addresses()` — `test_tls_certificate.ConnectsToTheValidatedAddress`;
   - the guard refuses any address that is not `is_global` (shared address space 100.64.0.0/10 included) —
     `test_shared_address_space_is_private_unless_the_run_allows_it`.

   Against HTTP-1, HTTP-2, HTTP-10: HTTP-1 lists the refused ranges without shared address space and says nothing of
   a checker that opens its own socket; HTTP-2 already lists carrier-grade NAT among the allowance's networks (no
   edit); HTTP-10 covers one response and not a walk over many. HTTP-1 and HTTP-10 are amended. What a site's own
   word may make the audit request — a sitemap on another host, a port other than the web ports — is neither, so it
   is a new requirement, HTTP-13, holding both 0.167.0's sitemap host rule and 0.168.0's switch.
4. **GOV-2's count.** It says "66 of 160" twice, the governance open question says "Sixty-six of 160", and
   `evidence`'s open question says "66 of 160"; `audit_thresholds.py` counts 163. `tests/test_prose_counts.py` binds
   the GOV-1 paragraph's numbers and none of these four sentences, which is why it stayed green. The four are bound
   by new claims, seen red on the stale numbers first.
5. **Process.** `templates/sprint-contract.md` gets a "Spec requirements touched" line; `AGENTS.md` says a spec edit
   goes in the same commit as the code that changes the behaviour.
